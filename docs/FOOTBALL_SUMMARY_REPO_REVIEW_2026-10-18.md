# Football-summary repository: usefulness for ArenaVoca

Reviewed: 2026-10-18. Read-only source inspection of [`ahmadalhriri/ai-football-match-summary` at `05c972dba28e45a80a6a447bc2512fd4351101ce`](https://github.com/ahmadalhriri/ai-football-match-summary/tree/05c972dba28e45a80a6a447bc2512fd4351101ce). No dependency installation, external code execution, checkpoint loading, media download or performance experiment was performed. The observations below apply to this revision, not every future revision.

## Finding

**Research judgment:** useful inspiration for a local candidate-moment detector, especially player/ball tracking; unsuitable as a ready-made action-understanding or Spanish-learning engine. Its implemented video event rules are much weaker than its README's broad summary claims. The safest useful experiment would compare detector-assisted candidate selection with ArenaVoca's current bounded recorded-window baseline. This is a proposal, not an accepted implementation change.

ArenaVoca already has FFmpeg preparation, optional local Whisper transcription, a local vision-language adapter and explicit review states. Current source separates visual/commentary evidence and withholds uncertain/replay observations; its observed football errors remain documented. The new capability worth evaluating is persistent spatial evidence from detections/tracks, rather than replacing our viewer, companion or review contract. Sources: [local adapter](../app/src/features/match-recognition/local_model.py), [review policy](../app/src/features/match-recognition/recognize.py), [existing evidence](wiki/recognition.md), [Windows trial report](WINDOWS_LOCAL_AI_2026-10-16.md).

## Material source-level limitations

**Timing defect inferred from the code, not measured in a run:** `parallel_extract()` defaults to every second source frame; detection reindexes sampled images consecutively; fusion assumes `frame_step = 1` and divides by the original video's FPS. Under the active default path, sample 100 represents source frame 200 but is converted as frame 100. For 25 fps, that is 4 seconds instead of 8. This undermines both audio matching and clip selection. Sources: [extractor 32–60](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/read/video_utils.py#L32-L60), [main 47–48](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/main.py#L47-L48), [tracker 130–143](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/trackers/tracker.py#L130-L143), [merger 42–74](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/mareg_voice_vidoe/MomentsMerger.py#L42-L74).

**Batch processing, not a demonstrated live recognizer:** the API downloads a video, chooses the newest local file, extracts frames and performs the complete pipeline before returning. Shared scratch paths and in-request processing do not establish safe concurrent jobs or streaming behavior. The download endpoint deletes the selected original after summarization. ArenaVoca should retain its private original benchmark and source timing, not adopt this lifecycle. Sources: [main 27–78](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/main.py#L27-L78), [229–258](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/main.py#L229-L258). The README itself lists live broadcasting among future work. [README 253–260](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/README.md#L253-L260).

**Reproducibility/evidence gaps:** the pinned tree contains two detector checkpoints, but no training script/notebook, dataset configuration, model card, held-out action/detection metrics or backend tests. The visible Flutter test is a generated counter smoke test. No measured end-to-end latency, full-match accuracy or Quest acceptance follows from source inspection. The dependency manifest omits direct imports `sentence_transformers`, `sklearn` and `rich`; several ML dependencies have only lower bounds. The actual detector forcibly requests CUDA, despite README describing CUDA as optional. Sources: [pinned file tree](https://github.com/ahmadalhriri/ai-football-match-summary/tree/05c972dba28e45a80a6a447bc2512fd4351101ce), [models directory](https://github.com/ahmadalhriri/ai-football-match-summary/tree/05c972dba28e45a80a6a447bc2512fd4351101ce/backend/FastAPIserver/models), [test](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/test/widget_test.dart), [requirements](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/requirements.txt), detector/classifier/team source above. ## Reuse and next decision

**Observed licensing evidence:** README says MIT, but this pinned tree has no standalone license text/copyright notice and GitHub repository metadata reports `license: null`. This is incomplete reuse evidence, not proof that all reuse is forbidden. Model training-data provenance and checkpoint redistribution terms are also undocumented. Do not infer that a README's MIT statement covers dependencies or weights. Resolve code/checkpoint terms before copying them into ArenaVoca. Sources: [README 242–244](https://github.com/ahmadalhriri/ai-football-match-summary/blob/05c972dba28e45a80a6a447bc2512fd4351101ce/README.md#L242-L244), [pinned tree](https://github.com/ahmadalhriri/ai-football-match-summary/tree/05c972dba28e45a80a6a447bc2512fd4351101ce), [repository API metadata](https://api.github.com/repos/ahmadalhriri/ai-football-match-summary). Metadata is the dated default-branch observation; the source links are commit-pinned.

**Proposal:** keep the accepted prepared-card Quest milestone intact. If recognition research is authorized, first evaluate a suitably licensed detector on a small, manually annotated set of recorded windows containing the target sequence, ordinary play, camera cuts and replays. Preserve original source timestamps and mark every interpolated position. Compare existing VLM-only results with detector-assisted candidates using action precision/recall, timing error, duplicate/replay rate, useful-card yield, wall time and GPU memory. Feed reviewed evidence into the existing Spanish-card contract; do not let candidate detection manipulate match playback.

Ultralytics separately offers AGPL-3.0 and Enterprise licensing for its code/models. Review those terms for the intended integration; the external app's README cannot override them. This records the publisher's licensing options, not a legal determination about ArenaVoca. [Official Ultralytics licensing](https://www.ultralytics.com/license).

**Unresolved:** which detector has adequate tiny-ball accuracy and usable license/provenance; whether tracking survives our broadcast cuts; whether spatial evidence improves action descriptions enough to justify its compute cost; and whether detector-assisted sampling outperforms the existing bounded baseline. This repository supplies an experiment idea, not answers to those questions. [ArenaVoca recognition evidence and next checks](wiki/recognition.md).
